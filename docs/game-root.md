# 游戏根目录与迁移

启动器空闲时，可在设置中输入游戏根目录或通过“浏览”选择文件夹，已有实例不会锁定浏览按钮。任务执行中和游戏运行中暂时禁用修改。

首次运行默认使用 exe 所在目录下的 `game` 文件夹并自动创建；通过快捷方式从其他工作目录启动也不改变这个位置。直接运行 jar 时使用 jar 所在目录，Gradle/IDE 使用项目工作目录。已有配置继续使用已保存的路径，不擅自改动或迁移。

保存不同游戏根目录时弹出统一 Win95 风格对话框：

- **迁移并重启**：将旧游戏根目录中的实例、存档、模组、共享依赖库、资源文件及其他游戏文件迁移至空目标目录。
- **不迁移，仅重启**：保留旧目录文件，保存新路径并在重启后读取新目录中的实例。新目录不存在时创建；已有实例不会覆盖。
- **取消**：不保存、不迁移、不重启。

同一真实目录的路径别名不会触发迁移和重启。游戏运行时禁止修改设置。

迁移在后台执行：临时目录复制 → 逐文件比较和源目录变更检测 → 发布目标目录 → 保存设置与实例登记 → 清理旧文件 → 重启。
存档和模组位于实例目录或共享游戏根目录时都会包含在迁移中。目标必须为空；拒绝目录互相包含、磁盘根目录、目录链接，以及包含启动器程序或配置数据的源目录。
复制、校验、扫描或设置保存失败时，原配置和实例登记不变，源文件保留，回滚本次复制。跨盘也采用复制校验流程，不依赖同盘重命名。

清理旧文件仅在目标与设置完整保存后执行，且只删除清单内仍与目标一致的文件。发现新写入、链接替换或文件占用时停止清理并明确提示用户，保留完整目标以及无法清理的旧文件，不回滚到可能已部分清理的旧目录。
迁移提交期间不允许用户取消或正常关闭启动器；进度通过状态栏显示。操作系统强制结束进程不属于可回滚操作，复制阶段留下的临时目录可能需要手工清理；此阶段不会删除源文件。

测试覆盖默认目录定位、保留旧配置、迁移/不迁移/取消、自动重启请求、实例重新读取、保存失败回滚、非空目标、嵌套路径、目录链接、源文件变更、清理时父目录链接替换、文件完整性与临时目录清理。

打包验证使用独立临时配置与本地文件：从不同工作目录启动打包运行时，检查 exe 旁的默认 `game`，迁移后通过真实 exe 自动重启并生成界面快照，确认新路径、文件内容和目录锁释放。未对用户真实游戏文件进行测试性迁移。
