# 启动器可见性

设置页的“启动器可见性”保存到 `settings.json` 的 `launcherVisibility` 字段。
旧配置缺少字段时保持启动器可见。每次启动使用当时保存的策略，不在准备游戏文件时隐藏窗口。

| 模式 | 游戏启动成功后 | 游戏结束后 |
| --- | --- | --- |
| 游戏启动后结束启动器 | 退出启动器界面和主进程 | 不重新打开 |
| 游戏启动后隐藏启动器 | 隐藏窗口，保留进程监控 | 正常退出时结束启动器；异常退出时恢复窗口并提示 |
| 保持启动器可见 | 保留窗口 | 更新运行状态，异常退出时提示 |
| 隐藏启动器并在游戏结束后重新打开 | 隐藏窗口，保留进程监控 | 正常或异常退出均恢复原窗口 |

恢复窗口前清除最小化状态；隐藏期间关闭 JavaFX 隐式退出，防止最后一个窗口隐藏导致启动器意外退出。
启动前的认证、下载、Java 检测或创建进程失败不会触发隐藏或退出策略。

结束启动器模式使用随程序打包的 Java 运行时启动独立日志辅助进程。该进程启动游戏、读取合并的标准输出和错误输出，
对微软访问令牌脱敏后写入原日志目录，随游戏结束退出。它不包含 JavaFX，也不持有启动器数据目录锁。
命令和令牌通过进程标准输入传递，不新增包含令牌的临时文件或辅助进程命令行参数。

验证：四种模式的本地离线游戏启动、配置保存与旧配置兼容、窗口隐藏和恢复、异常退出恢复、
父进程退出后的独立日志写入和脱敏、辅助进程启动失败。UI 校验使用本地进程夹具，不依赖微软服务或真实游戏网络下载。

参考设计：[HMCL](https://github.com/HMCL-dev/HMCL) 的可见性策略及 JavaFX 生命周期处理，
[Prism Launcher](https://github.com/PrismLauncher/PrismLauncher) 的游戏任务与窗口分离。
沿用本项目现有依赖，未复制第三方实现代码。
