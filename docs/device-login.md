# 微软设备代码登录

点击“微软登录”会打开统一 Win95 风格弹窗，联系微软获取一次性用户代码、HTTPS 验证网址及有效期。
用户可复制代码，在系统浏览器打开微软验证网址并输入代码；弹窗展示剩余有效期。
代码由微软生成，启动器不接收微软密码，也不向用户展示私密的 `device_code`。

沿用 MSAL4J 1.26.0 的设备代码流程、服务器轮询间隔、现有 Client ID 与 `consumers` 端点。
不新增依赖；MSAL 获取授权后继续执行 Xbox、XSTS、Minecraft 权益及账号资料验证。
新登录使用独立的内存令牌缓存，验证全部成功后才写入现有 Windows DPAPI 加密缓存和账号文件；取消或验证失败不提前覆盖已有凭据。

取消按钮或关闭登录弹窗会取消当前认证任务并取消 MSAL Future。已排队的旧回调按任务身份过滤，不能重新打开弹窗或覆盖后续账号。
代码过期、拒绝授权或公共客户端配置错误会显示中文提示。等待期间可以点击“刷新代码”，取消旧请求并创建新的授权会话。
剩余时间使用单调时钟，并从发起请求时保守计算，避免系统校时或网络耗时导致倒计时变长；它是预计时间，不代表一次性代码一定未被消费或撤销。
微软授权一旦完成，立即清除代码、停止倒计时并禁用复制、打开与刷新，继续显示游戏账号验证状态。
打开微软 `/link` 页面时携带当前代码的 `otc` 参数，替换旧页面或旧链接中残留的代码；其他验证网址按微软原样打开。
微软应用注册需允许公共客户端流程，Minecraft API 的应用准入与账号权益校验仍然适用。

测试使用实际 MSAL4J 加本地模拟 HTTP 响应，覆盖获取代码、等待授权、成功、取消后停止轮询、过期、拒绝和应用配置错误。
JavaFX 测试覆盖弹窗样式、复制、关闭取消、成功自动关闭、过期按钮禁用、旧回调不能覆盖离线账号。
回归补充网络耗时扣除、单调倒计时、当前代码链接绑定、授权成功立即清除代码、刷新创建新会话。
用户报告的“网页提前提示过期”尚未在真实微软网页上完整复现；真实端点新代码可正常等待授权，以上修复针对已确认的计时与一次性代码状态缺陷，不宣称改变微软服务端有效性判定。
本地夹具测试不代表已完成真实微软账号授权；真实登录仍需用户在微软网页完成。

2026-10-29 使用内置 Client ID 对真实微软设备代码端点进行了仅获取代码的检查，服务返回 `AADSTS70002`，提示应用必须标记为 mobile。
应用所有者随后启用了公共客户端流程；同日重新请求真实微软端点，成功返回有效登录代码与验证网址，原 `AADSTS70002` 阻塞已解除。
检查在收到代码后主动取消，没有完成账号授权，也没有保存或输出任何用户代码、设备代码或令牌。完整账号登录仍需用户在微软网页完成。
