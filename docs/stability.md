# 稳定性与恢复

## 参数与内存

参数编辑文本与参数列表采用配套的引号/反斜杠规则，保留空参数、空白、单双引号、UNC 路径和末尾反斜杠。
这不是 shell 命令执行器；启动仍将参数列表直接交给 `ProcessBuilder`，不会拼接到命令行解释器中执行。
内存先解析数值，再检查换算前的上限，最后转换单位。手动 JVM 参数的最小内存范围为 128–65536 MB，最大为 512–65536 MB。
旧实例缺少最小内存的 256 MB 迁移规则保留；手动输入 0 不会再误用这条迁移规则。

## 安装权限

安装器为当前用户安装，默认 `%LOCALAPPDATA%\Programs\FuzzLauncher`，不为程序目录授予所有用户写权限。
程序旁的 `game/data/baseVerisons` 由当前用户创建和使用。打包排除已有的这些目录，避免夹带游戏数据、账号或配置。
旧的 Program Files 安装和手动选择的不可写目录不会自动迁移或放宽权限；升级时应选择用户可写位置并保留原数据。

## 操作恢复记录

安装、加载器重装和启动器设置保存使用稳定配置位置下的 `operations/<操作ID>/operation.json`。
稳定位置为 `DataLocations.bootstrapDirectory()`，正常安装对应 `%LOCALAPPDATA%\FuzzLauncher`；显式 `fuzz.dataDir` 则使用指定位置。
它独立于正在切换的游戏/数据目录；启动时在解析数据目录迁移之前检查恢复记录。

- `PENDING`：修改目标之前保存备份、目标位置和预期新内容的 SHA-256，目录发布记录文件清单。未提交操作可回退。
- `COMMITTED`：文件和配置提交完成；之后只清理私有临时文件，不回退有效安装或设置。
- `ROLLED_BACK`：回退完成；只需继续清理私有文件。清理被再次中断也可重试。

恢复在后台执行。用户明确选择“恢复或清理并继续”才开始；关闭弹窗或选择退出会保留所有记录。
存在待处理记录时不接受新的持久化操作。恢复期间和正常提交阶段不接受取消，避免产生新的半提交状态。
引导目录锁保护恢复与正在运行的启动器操作，不允许另一个实例同时恢复。

恢复前核对快照和目标指纹，遇到外部修改、新增用户文件、目录链接或损坏备份时停止，保留材料供检查。
目录迁移只在配置提交后清理源目录；崩溃后恢复不会自动继续删除旧源目录。
数据文件目录迁移仍使用原有的来源指针和复制标记重试，同时迁移配置备份及本地 `config` 覆盖文件。
共享的已下载缓存不会作为“无主文件”批量删除。

文件内容和记录写入后执行文件刷盘，再进行原子替换；不支持原子替换时使用现有替换回退。
已覆盖独立测试进程被强制结束后的恢复。硬盘损坏、系统丢失刷盘数据或恢复记录自身损坏不能保证自动恢复，遇到校验不一致时会停止而非猜测覆盖。

## 配置备份

`settings.json.bak` 和 `instances.json.bak` 保存有效的上一代配置；首次保存时建立有效备份。
保存前校验当前配置，损坏内容不会被滚动写进有效备份。整数、枚举和实例清单结构均在加载边界检查。
损坏时显示文件位置及字段/原因，提供恢复有效备份、打开目录、修复后重新读取和退出。
恢复前以 `.corrupt-<ID>` 保留原损坏文件。没有有效备份时不会显示恢复按钮，也不会静默重置为空配置。

## 取消和资源释放

大文件复制、校验使用有界循环检查取消；取消后关闭流并清理本次创建的部分文件。
Java 探测和安装处理器使用统一的进程树终止与等待逻辑，释放句柄后再清理临时文件，保留线程中断状态。
下载等待许可的任务可以取消，只有真正取得许可的任务才释放许可。
启动器退出会等待后台任务完成清理；超时则把目录锁留到进程结束，并保留恢复记录供下次启动处理。

## 本地验证

测试覆盖参数往返、内存溢出/下限、配置损坏和恢复、操作日志回退/提交、外部文件冲突保护、迁移回退、取消复制、下载许可释放，以及独立进程被强制结束后的恢复。
界面测试覆盖 Win95 恢复弹窗、恢复备份、退出保留记录和再次进入恢复。安装器使用最小编译夹具检查脚本及数据排除规则，不执行真实系统安装。
未执行真实 Minecraft 游戏、联网加载器安装、物理断电或旧管理员安装升级测试。
